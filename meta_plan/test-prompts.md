# CEL A/B 评价 —— 测试提示词模板

> 两类提示词的核心差异：实验组必须加载 CEL 技能并执行其协议；对照组不加载 CEL，由 Agent 自由发挥。

---

## 一、对照组提示词模板 (Control)

对照组的目标是让 Agent 以"默认/原生"行为完成任务，不受 CEL 影响。

### 1.1 通用对照组模板

```
你是一个软件工程助手。请完成以下任务。

## 任务

{task_description}

## 要求

- 请完成上述任务。
- 完成后请说明你做了什么。

当前工作目录：{workspace_path}
```

### 1.2 对照组关键约束

- **不包含任何 CEL 触发词**："稳妥地做"、"逐步推进"、"最小修改"、"先验证再继续"、"收敛"、"误差度量" 等均不出现在提示词中
- **不加载 CEL skill 文件**：如果平台支持技能系统，确保 CEL skill 未被激活
- **不给策略指导**：不说"先分析再动手"、"每次只改一处"等 —— 完全由 Agent 自主决定工作方式

---

## 二、实验组提示词模板 (CEL)

实验组的目标是让 Agent 加载 CEL 技能并严格按其协议执行。

### 2.1 通用实验组模板

```
请使用"收敛式工程迭代"技能完成以下任务。遵循技能的全部协议：每轮做最小更新、通过外部验证判断改进、误差下降则接受、上升则回滚、满足停止条件时停止。

## 任务

{task_description}

## 要求

- 加载并遵循 convergent-engineering-loop 技能的全部协议。
- 使用对应参考文件定义误差度量。
- 每轮输出迭代报告（含误差值、决策、下一步）。

当前工作目录：{workspace_path}
```

### 2.2 实验组关键约束

- **必须包含 CEL 触发词**："收敛式工程迭代"（skill name）、"最小更新"、"误差度量"等
- **确保 CEL skill 已安装并加载**：如果平台支持技能系统，确保 skill 已部署到项目

### 2.3 按领域的实验组提示词细化

不同领域需给出领域特定的触发词，确保 Agent 选择正确的参考文件。

#### 代码开发领域（T01-T04）

```
请使用"收敛式工程迭代"技能，逐步推进。每轮只做最小代码修改，通过运行测试验证改进，误差下降则接受、上升则回滚。
```

## 三、平台适配

### 3.1 CodeBuddy

在 CodeBuddy 中，实验组对话的第一条消息必须以 CEL skill 触发词开头。对照组的对话内容不含任何 CEL 触发词，且如果平台支持，应在对话前确认 CEL skill 未被自动匹配。

### 3.2 Claude Code

同上。Claude Code 的 skills 加载机制为自动匹配，实验组对话需包含触发词，对照组避免。

### 3.3 Codex

Codex 的目标模式下，实验组提示词需额外包含目标模式指令（见 `_shared/skills/convergent-engineering-loop/templates/目标模式提示词.md`）。对照组不使用该模板。

---

## 四、多轮对话管理

### 4.1 单轮限制

为防止单次对话无限延长（Token 耗尽），设定**每任务最大轮次上限**：

| 复杂度 | 最大轮次 |
|:------:|:--------:|
| 简单 | 10 |
| 中等 | 20 |
| 复杂 | 35 |

超过上限未完成的记作"失败"。

### 4.2 对话停止规则

- Agent 主动声明"任务完成" → 人工确认后停止
- 达到最大轮次 → 强制停止
- Agent 请求用户确认且用户无更多输入 → 停止（记作"需人工介入"）

### 4.3 多轮会话续接

如果平台不支持超长单次对话，实验组需按 CEL 分批迭代协议在批次间传递上下文。对照组不做特殊处理，如果中断则在下一会话中告知"请继续完成未完成的任务"。
